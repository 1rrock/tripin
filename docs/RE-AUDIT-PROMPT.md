## 규칙 — 이게 제일 중요하다

- **추측을 결함으로 보고하지 마라.** 각 항목은 재현하거나 소스를 직접 열어 확인하라.
  못 한 것은 "미확인" 이라고 **명시**하라. 확인된 것과 섞지 마라.
- **틀렸다고 판명되면 그렇게 적어라.** 직전 세션에서 "404 본문이 빈 건 `use client`
  탓" 이라는 가설을 실험으로 반증했다. 그런 반증이 추측보다 값지다.
- **이미 고친 것을 다시 지적하지 마라.** `git log -12` 와 HANDOFF §2 를 먼저 봐라.
- **열려 있는 3건(HANDOFF §5)은 이미 안다.** 새로 보고하지 말고, 그것에 대해
  **새로운 정보**가 있을 때만 말하라.
- 코드를 고치지 마라. 이번엔 진단만이다.

## 검증 방법

- 런타임은 프로덕션 빌드로 봐라: `rm -rf .next && npm run build && npm run start`.
  dev 서버의 동작은 다르다(상태 코드·정적화 판정이 특히).
- `npx tsc --noEmit` 의 `.next/**/validator.ts` 에러는 가짜다 —
  `grep -v '^\.next/'` 로 걸러라(HANDOFF §3-11).
- **지도는 도구로 검증할 수 없다.** 자동화 브라우저에 WebGL 이 없다(HANDOFF §3-10).
  지도 인터랙션이 얽힌 항목은 유저 확인을 요청하라. 스크린샷이 두 번 실패하면
  `javascript_tool` + `getBoundingClientRect()` DOM 실측으로 전환하라.
- 레이아웃·대비는 캡처가 아니라 DOM 실측으로 판단하라. 단, **조건부로 렌더되는 UI**
  (드롭다운 패널 등)는 정적 스캔이 못 잡는다 — 열어서 봐야 한다. 직전 점검이
  대비 위반 1건을 그렇게 놓쳤다.
