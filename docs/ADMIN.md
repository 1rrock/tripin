## 1장. 인증과 보호

### 1.1 방어선은 셋이다

| # | 자리 | 무엇을 막나 | 파일 |
|---|---|---|---|
| 1 | proxy(middleware) | `/admin/*` · `/api/admin/*` 요청 경로 | `src/proxy.ts` |
| 2 | `(protected)` 레이아웃 | 어드민 **화면** 렌더 | `src/app/admin/(protected)/layout.tsx` |
| 3 | `requireAdmin()` | 서버 액션 **한 건 한 건** | `src/shared/lib/require-admin.ts` |

셋이 겹치는 것은 낭비가 아니다. proxy 는 matcher 회귀·`config` 오타·미들웨어 우회
취약점 하나로 통째로 무력화된다. 그때 열리는 것이 장소 DB·신청자 이메일·삭제요청자
연락처다. 서버 액션은 `"use server"` 함수라 리팩터링으로 middleware 를 안 거치는
호출 경로가 생길 수 있어 3번이 따로 있다.

`/admin/login` 만 `(protected)` **밖**(`src/app/admin/login/`)에 산다. 로그인 하나를
열어 두고 나머지를 전부 잠그는 구조다. 라우트 그룹 괄호는 URL 에 안 나타나므로 경로는
그대로다.

### 1.2 실패는 404 로 끊는다

401·403 은 "여기 어드민이 있다"를 알려 준다. 그래서:

- 미인증 화면 진입 → `notFound()` (레이아웃)
- `ADMIN_SECRET` 미설정 + 프로덕션 → proxy 가 **404**
- `ADMIN_SECRET` 미설정 + 개발 → `/admin/login?error=nosecret` 로 리다이렉트

### 1.3 쿠키는 비밀번호를 담지 않고, **서명 키도 비밀번호가 아니다**

`tripin_admin` 쿠키 값은 `만료시각.HMAC-SHA256(서명키, "admin:만료시각")` 이다
(`shared/lib/admin-auth.ts`). 수명 **7일**(`TOKEN_TTL_SEC`) — 재로그인 부담과 노출
위험의 절충.

🔑 **서명 키 = `HMAC(ADMIN_SECRET, "eatripin:admin-cookie:v1")`.** 비밀번호 원문이
아니다. 2026-08-24 이전에는 `ADMIN_SECRET` 이 로그인 비밀번호이자 HMAC 키였다 —
한 값이 두 역할을 했고, 그게 이 문서의 유일한 열린 항목이었다.

유도 방식을 고른 이유: 두 번째 시크릿을 env 로 두면 **사람이 값을 정하고 보관해야
하고**(회전 정책 결정이 필요해진다) 도입 순간 기존 세션이 전부 끊긴다. 유도는 둘 다
필요 없다 — 새 env 0개, 그리고 `LEGACY_SIGNATURE_UNTIL`(2026-09-07) 까지 옛 서명도
받아 주므로 세션도 안 끊긴다. 그 날짜가 지나면 옛 경로는 **저절로 닫힌다**.
쿠키 수명이 7일이라 실제로는 그 전에 이미 다 갈린다.

라벨(`info`)을 고정 문자열로 두는 이유: 나중에 같은 비밀번호에서 **다른 용도**의
키가 필요해지면 라벨만 바꿔 서로 섞이지 않는 키를 하나 더 뽑는다. 라벨 없이
유도하면 그 순간 다시 "한 값이 두 역할" 로 돌아간다.

실측 검증(로컬 프로덕션 빌드): 미인증 307 · 로그인 후 200 · 발급 서명이 유도 키
서명과 일치하고 원문 키 서명과 **불일치** · 옛 형식 쿠키 200(전환 창) · 위조 서명 307 ·
만료된 옛 쿠키 307.

- proxy(Edge)와 route handler(Node) 양쪽에서 돌아야 해서 `node:crypto` 를 안 쓰고
  Web Crypto(`crypto.subtle`)만 쓴다.
- 비교는 전부 **해시끼리**다(`secretMatches`). 원문을 직접 비교하면 입력 길이가
  타이밍으로 새어 나간다. 양쪽을 SHA-256 으로 접어 길이를 같게 만든 뒤 상수시간 XOR.
- `ADMIN_SECRET` 이 **16자 미만이면 미설정으로 친다**(`getAdminSecret`). 약한 시크릿으로
  열리느니 잠기는 쪽을 고른다.

### 1.4 실패 잠금 — 키는 위조 불가능한 칸이어야 한다

IP 당 5회 실패 → 60초 잠금(`api/admin/login/route.ts`).

🔴 **`x-forwarded-for` 의 맨 왼쪽으로 키잉하지 마라.** 그 칸은 클라이언트가 직접 보내는
값이라, 매 요청 다른 값을 넣으면 카운터가 매번 새 키로 갈려 **잠금이 영영 안 걸린다.**
2026-08-24 이전에 실제로 그랬고 실측 8/8 통과였다. 지금은 이 순서로 읽는다:

1. `x-real-ip` (Vercel 이 붙인다)
2. `x-vercel-forwarded-for`
3. `x-forwarded-for` 의 맨 **오른쪽** — 가장 가까운 프록시가 붙인, 위조 불가능한 유일한 칸

메모리 카운터라 서버리스 다중 인스턴스에서는 느슨해진다. 1인 어드민에는 충분하다.

### 1.5 `ADMIN_SECRET` 회전

회전은 **여전히 사람이 한다**(env 값을 바꾸는 일이라 그렇다). 다만 바꿀 때 알아둘 것:

- 값을 바꾸면 **비밀번호와 서명 키가 같이 바뀐다**(서명 키가 비밀번호에서 유도되므로).
  즉 기존 세션이 전부 끊기고 재로그인이 필요하다. 1인 어드민이라 한 번 로그인하면 끝이다.
- **16자 미만으로 바꾸지 마라** — `getAdminSecret()` 이 미설정으로 취급해서
  프로덕션이 404 로 잠긴다(1.2). 잠기는 쪽이 열리는 쪽보다 낫다는 판단이지만,
  모르고 밟으면 "사이트가 죽은" 것처럼 보인다.
- 1.3 의 유도 덕에 "두 역할" 문제 때문에 **급히** 회전해야 할 이유는 없어졌다.

### 1.6 색인 금지

`src/app/admin/layout.tsx` 의 metadata 가 `robots: noindex`. `robots.ts` 의 차단과
이중 방어다. 어느 한쪽만 두지 마라 — robots.txt 는 권고고, 메타는 이미 크롤한
페이지에도 적용된다.

## 4장. 데이터 원칙

- 공개 화면은 `is_published = true` 인 것만 그린다. RLS 가 그 판정을 한다.
- 어드민은 `service_role` 로 읽고 쓴다 — RLS 를 **전부 우회**한다.
  절대 클라이언트로 넘기지 마라(`shared/config/env.ts`).
- 쓰기 뒤에는 `purgePublicData()` 로 서버 캐시 + CDN 사본을 같이 비운다.
  공개 JSON 라우트 8개가 전부 `Cache-Tag: public-data` 를 단다 —
  **새 공개 라우트를 만들면 같이 달아라.** 태그가 갈라지면 어드민 퍼지가 그 CDN
  사본을 못 지운다.
- 스크립트(`scripts/ingest/*`)는 공개 캐시를 **안 비운다.** 프로덕션은
  `vercel cache invalidate --tag public-data`.

## 5장. 확정 잠금

**동명이점 오확정은 이 프로젝트의 유일한 구조적 리스크다**(`0001_init.sql:121`).
2026-08-18 후쿠오카 배치에서 실제로 무더기로 났고, 자동 복구가 불가능했다.

그래서 `map_status = 'confirmed'` 로 저장하려면 **둘 다** 있어야 한다
(`admin/(protected)/confirm/actions.ts` — 신규·수정 경로 양쪽에 같은 검사):

1. **좌표** — 구글 공유 링크(`maps.app.goo.gl`)나 네이버 장소 링크를 넣으면 자동으로 채워진다
2. **근거(`source_note`)** — 영상 속 간판 / 지역 언급 / 타임스탬프 중 하나

없으면 저장이 거부된다. 경고가 아니라 **거부**다 — 6장의 요약 검사와 정반대 방침이고,
그 차이가 의도된 것이다. 요약이 어설픈 것은 고칠 수 있지만 엉뚱한 가게를 확정한 것은
누가 신고하기 전까지 아무도 모른다.

`confirmed` = `is_published = true` 다(같은 트랜잭션에서 함께 세운다).

### 5.1 퍼지 텍스트 검색을 다시 쓰지 마라

`scripts/ingest/reclassify-place-types.mjs` 는 **기존 `google_place_id` 로 Places

`SummaryEditor` 의 "참고 자료"(자막 파생물)에는 **복사 버튼이 없다.** 자막을 그대로

템플릿은 네 칸이다: `[무엇]` · `[어디]` · `[영상 맥락]` · `[실용 정보]`.

실시간 검사(`runLocalChecks`):

| 검사 | 기준 |
|---|---|
| 불릿 수 | 3~5개 |
| 글자 수 | 40~200자 |
| 금지어 | 진짜 · 미쳤 · 인생 · 존맛 · 대박 · JMT |

이유가 그대로 우리 몫이 된다.

## 7장. 번역 검수

`/admin/translations`. `places.en_source` 가 세 상태를 가른다(`shared/i18n/display.ts`
`displaySummary`):

| `en_source` | EN 화면 |
|---|---|
| `null` | 영문 요약을 **숨긴다** |
| `'machine'` | 영문 + "자동 번역" 표시 + 원문 토글 |
| `'human'` | 영문 그대로 (표시 없음) |

`scripts/translate-en.mjs` 는 `'machine'` 으로만 쓴다. 검수하면 `'human'` 이 된다.

⚠️ **`en_source` 는 산문(요약·불릿·가격힌트)의 출처 표시다.** 상호명(`name_en`)과는
무관하다 — `translate-en.mjs --names` 는 이 컬럼을 건드리지 않는다. 이름만 채우고
`machine` 을 찍으면 번역되지도 않은 빈 요약이 "자동 번역된 요약"으로 나가고, 산문
번역 대상(`en_source is null`)에서도 영영 빠진다.

상호명은 검수 표시가 없다 — 화면이 `name_en → name_local → name` 순으로 고르고
(`displayPlaceName`), 간판 표기는 보조줄에 그대로 남는다.

## 8장. 삭제·정정 요청

### 8.1 큐 (`/admin/queue`)

**법정 절차다.** 정보통신망법:

| 조항 | 요구 |
|---|---|
| §44조의2② | **지체 없이** 조치하고 신청인·게재자 **양쪽**에 통지 |
| §44조의2④ | 임시조치는 **30일 이내**에 결론 |
| §44조의3 | 신고가 없어도 선제적 비공개 가능 |

그래서 화면이 "비공개"를 먼저 쉽게 만들고 되돌리기를 나중에 둔다. 기한이 지난 건은
목록 맨 위로 올라온다.

`blindTarget(id)` 이 끄는 스위치는 대상 타입마다 다르다:

| `target_type` | 끄는 것 |
|---|---|
| `place` | 그 장소만 |
| `creator` | 채널 전체 (RLS 가 `creators.is_published` 로 즉시 차단) + 딸린 장소도 같이 |
| `video` | 그 영상에 걸린 장소 전부 |
| `other` | 자동 처리 없음 — 손으로 |

⚠️ 대상이 실제로 있었는지(`targetFound`)를 켠 장소 수와 **따로 센다.** 예전에는 대상이
이미 없어도 status 를 `blinded` 로 마감했다 — 임시조치가 된 적 없는 요청이 처리된 것처럼
큐에서 사라지고 30일 시계만 돌았다.

`closeRequest` 도 같은 규율이다: 0행 업데이트를 성공으로 읽지 않는다.

### 8.2 인입 경로 (2026-08-24 신설)

```
/takedown 폼 → POST /api/takedown → submit_takedown_request (0021, definer RPC)
```

⚠️ 이 화면이 생긴 뒤로도 **빈 목록을 "요청 없음"으로 읽지 마라.** 메일(mailto:)로 오는
접수는 자동으로 이 큐에 안 들어간다 — 운영자가 손으로 옮겨야 한다.

접근 모양은 `channel_applications`(0013) · `search_misses`(0008)와 같다:

- 테이블은 RLS 켜짐 + **정책 0개** → anon 이 직접 못 만진다
- 쓰기는 `security definer` RPC 를 **service_role 라우트만** 부른다
  (PostgREST 는 테이블 정책 없이도 함수를 `/rpc` 로 노출하므로 실행 권한을 잠근다)
- IP 별 분당 3건 상한은 라우트에 있다

🔴 `0006` 이 지운 "누구나 INSERT"(`with check(true)`, roles=public) 정책을
**되살리지 마라.** anon 키는 클라이언트 번들에 노출되는 게 전제라 그 정책은 "키를 아는
아무나 무제한 INSERT" 와 같았다.
(`ROADMAP.md` 3단계가 "0006 의 패턴을 재사용한다"고 적어 뒀는데, 0006 은 그 정책을
**지운** 파일이다. 살아 있는 패턴은 0013 쪽이다.)

라우트는 붙여넣은 URL 에서 대상을 읽어 `target_id` 까지 붙인다 —
`/place/<slug>` · `/c/<slug>` · `/c/<slug>/v/<youtubeId>`. 해석 실패는 `other` 로
남기고 **접수는 그대로 진행한다.** 판정보다 접수가 우선이다.

⚠️ `URL.pathname` 은 퍼센트 인코딩된 경로를 준다. 확정 장소 slug 는 대부분 한글이라
디코딩하지 않으면 대상이 영영 안 붙는다(실측으로 당했다 — `target_type` 은 맞는데
`target_id` 만 null).

### 8.3 실패해도 접수는 남아야 한다

- RPC 가 실패하면 라우트가 500 을 준다. 폼은 그때 **메일 주소를 문구에 넣어** 보여준다
  (`messages.takedownForm.errorFailed` 의 `{email}`) — 남는 길이 그것뿐이다.
- 그래서 `/takedown` 화면에서 메일 주소를 **치우지 마라.**
- 알림 메일(Resend)은 접수의 **부속**이다. 메일이 죽어도 접수는 204 로 끝난다.

## 9장. 어드민을 만질 때의 규율

1. **조용히 실패하지 마라.** supabase-js 는 throw 하지 않는다. `error` 를 안 받으면
   조회 실패가 빈 배열이 되어 "요청 없음"·"할 일 없음"으로 화면에 나간다. 빈 것보다 나쁘다.
2. **0행 쓰기를 성공으로 읽지 마라.** `{ count: "exact" }` 로 받아 확인한다.
3. **새 공개 라우트에는 `Cache-Tag: public-data`.** 4장.
4. **서버 액션 첫 줄은 `await requireAdmin()`.** 1.1의 3번 방어선이 그것 하나다.
5. **DB 스크립트는 인자 없이 돌리면 dry-run.** 쓰려면 `--apply`.
   돌리기 전에 dry-run 출력을 사람에게 보여라.
