# Tripin — i18n (ko / en) 개발 가이드

> 공개 화면은 **한국어·영어**를 지원한다.  
> 이후 기능·화면을 추가할 때 **항상 두 로케일을 같이** 고려한다.  
> 작성: 2026-08 · 구현 상태: UI 크롬 i18n 적용, 콘텐츠(요약) 다국어는 점진.

관련: `PRODUCT.md` (KR 우선 · EN Phase) · `src/shared/i18n/*` · `src/proxy.ts`

---

## 0. 30초 요약

| 규칙 | 내용 |
|------|------|
| 기본 로케일 | **ko** — URL 접두사 없음 (`/city`) |
| 영어 | **`/en` 접두사** (`/en/city`) — proxy rewrite |
| UI 문구 | `messages/ko.ts` + `messages/en.ts` 에 **양쪽 동시** 추가 |
| 링크 | 하드코딩 `href="/city"` 금지 → `localePath(...)` 또는 `useLocale().href(...)` |
| 언어 전환 | `LanguageSwitch` 는 **`<a>` 풀 로드** (Link 소프트 네비 금지 — rewrite 한계) |
| 어드민 | **i18n 대상 아님** — 항상 한국어 |
| 콘텐츠 요약 | 메시지 파일이 아님 — DB. 지금은 ko 요약, en 필드는 추후 |

**새 화면 PR 체크:** “EN URL에서 메뉴·제목·빈 상태가 영어인가?” / “링크가 `/en/...` 를 유지하는가?”

## 1. URL · 라우팅

```
/                  → ko 홈
/city              → ko 지역
/en                → en 홈
/en/city           → en 지역
/admin/*           → 로케일 없음 (ko UI 고정)
/api/*             → 로케일 없음
```

### proxy (`src/proxy.ts`)

1. `/en` · `/en/*` → 내부 경로로 **rewrite** + 헤더 `x-tripin-locale: en`
2. 그 외 공개 경로 → `x-tripin-locale: ko`
3. `/admin` · `/api/admin` → 기존 인증 로직

**중요:** rewrite 때문에 내부 페이지 트리는 ko/en 이 같다.  
그래서 로케일만 바꾸는 네비게이션은 **반드시 풀 도큐먼트 로드**여야 한다  
(`LanguageSwitch` 가 `<a href>` 를 쓰는 이유).  
같은 로케일 안 이동(예: `/en` → `/en/city`)은 Next `<Link>` + `href()` 로 소프트 네비 OK.

### hreflang

새 공개 페이지는 `publicMeta()` (`src/shared/seo/page-meta.ts`) 를 쓴다.
canonical · OG · `ko`/`en`/`x-default` 를 한 번에 맞춘다. `x-default` 는 ko(기본 로케일).

```ts
import { publicMeta } from "@/shared/seo/page-meta";

export async function generateMetadata(): Promise<Metadata> {
  const locale = await getLocale();
  const m = getDictionary(locale);
  return publicMeta({
    locale,
    title: m.meta.homeTitle,
    description: m.meta.homeDescription,
    bare: "/city",
  });
}
```

손수 쓸 때도 짝은 같다:

```ts
alternates: {
  languages: {
    ko: "/city",
    en: "/en/city",
    "x-default": "/city",
  },
},
```

## 3. 서버 컴포넌트 패턴

```tsx
import { getDictionary, t } from "@/shared/i18n/get-dictionary";
import { getLocale, localePath } from "@/shared/i18n/locale";
import { displayCityName } from "@/shared/i18n/display";

export async function generateMetadata(): Promise<Metadata> {
  const locale = await getLocale();
  const m = getDictionary(locale);
  return {
    title: m.meta.homeTitle,
    description: m.meta.homeDescription,
    openGraph: { locale: locale === "en" ? "en_US" : "ko_KR" },
    alternates: { languages: { ko: "/", en: "/en" } },
  };
}

export default async function Page() {
  const locale = await getLocale();
  const m = getDictionary(locale);

  return (
    <main>
      <h1>{m.cityIndex.title}</h1>
      <p>{t(m.cityIndex.stats, { cities: 3, places: 10 })}</p>
      <Link href={localePath("/city/tokyo", locale)}>
        {displayCityName({ name: "도쿄", nameEn: "Tokyo" }, locale)}
      </Link>
    </main>
  );
}
```

### `t()` 치환

```ts
// messages: "간 곳 {places} · 도시 {cities}"
t(m.home.stats, { places: 10, cities: 3 });
// → "간 곳 10 · 도시 3"
```

## 4. 클라이언트 컴포넌트 패턴

공개 레이아웃이 이미 `LocaleProvider` 를 감싼다.

```tsx
"use client";
import Link from "next/link";
import { useLocale } from "@/shared/i18n/LocaleContext";

export function Foo() {
  const { locale, messages: m, href, t } = useLocale();

  return (
    <Link href={href("/channels")}>
      {t(m.home.channels, { n: 2 })}
    </Link>
  );
}
```

| API | 용도 |
|-----|------|
| `messages` / `m` | 문자열 카탈로그 |
| `href("/city")` | 현재 로케일 접두사 붙인 경로 |
| `t(template, vars)` | `{n}` 치환 |
| `locale` | `"ko"` \| `"en"` — 표시 폴백·조건부 렌더 |

`LocaleProvider` 밖(어드민 등)에서 `useLocale()` 호출 금지.

## 5. UI 문자열 추가 절차 (필수 순서)

1. **`messages/ko.ts`** 에 키 추가 (한글)
2. **`Messages` 타입**에 같은 키 추가 (`ko.ts` 하단 type — en 과 키 동기화용)
3. **`messages/en.ts`** 에 **영어 번역** 추가 (타입 에러 나면 누락)
4. 컴포넌트에서는 **하드코딩 한글/영어 금지** — `m.xxx` 만
5. EN 페이지(`/en/...`) 에서 눈으로 확인

```bash
npx tsc --noEmit   # en 키 누락 시 Messages 타입에서 잡힘
```

## 6. 데이터 표시 폴백 (`display.ts`)

| 필드 | ko | en |
|------|----|----|
| 도시 | `name` | `nameEn` 있으면 그것, 없으면 `name` |
| 장소 메인 | `name` | `nameLocal`(원어) 있으면 그것, 없으면 `name` |
| 장소 보조 | `nameLocal` | 원어를 메인으로 썼을 때 `name` |

```ts
import { displayCityName, displayPlaceName, displayPlaceSecondary } from "@/shared/i18n/display";

displayCityName({ name: "도쿄", nameEn: "Tokyo" }, locale);
displayPlaceName({ name: "무기토올리브", nameLocal: "むぎとオリーブ" }, locale);
```

### 인제스트·확정 시 (데이터 채울 때)

- 도시: **`name_en` 항상 채우기**
- 장소: **`name_local` 현지어 가능하면 채우기** (일본어·중국어 상호 등)
- 요약: 당분간 **한국어** `summary_bullets` (공개 EN 페이지는 요약 없이도 성립 — 폴백 UI)

## 7. 콘텐츠 다국어 (아직 / 앞으로)

| 단계 | 내용 |
|------|------|
| 지금 | UI i18n only. 요약은 ko |
| 다음 | `summary_bullets_en` 또는 jsonb 번역 컬럼 |
| 어드민 | 언어 탭으로 EN 요약 선택 입력 |
| 공개 | `locale === "en"` 이면 EN 요약, 없으면 짧은 폴백 문구 또는 요약 숨김 |

**기계번역 일괄 공개 금지** — 톤·법적 “독립적 가치”·품질. 핵심 조각부터 사람이 쓴 EN.

ja/zh UI 는 **별도 Phase**. 추가 시:

1. `config.ts` locales 확장  
2. `messages/ja.ts` …  
3. proxy: `/ja` 접두사 규칙  
4. LanguageSwitch 옵션 추가  

구조는 이미 “locale + dictionary” 이므로 확장 가능.

- [ ] 서버: `getLocale()` + `getDictionary(locale)`

- [ ] `/en/...` 에서 제목·메뉴·빈 상태·버튼이 영어

## 10. 빠른 디버그

| 증상 | 확인 |
|------|------|
| URL 만 바뀌고 문구 그대로 | 언어 스위치가 `<Link>` 인지 → `<a>` 여야 함 |
| EN 인데 한글 메뉴 | `getLocale` / proxy 헤더, 레이아웃 Provider |
| EN 링크가 `/city` 로 감 | `localePath` / `href()` 미사용 |
| 빌드 시 headers 에러 | 클라이언트가 `locale.ts` import |
| en.ts 타입 에러 | `Messages` 키 누락 |

```bash
# 스모크
curl -s http://localhost:3000/    | head   # 한국어 홈 문구
curl -s http://localhost:3000/en  | head   # Places you saw 등
```
