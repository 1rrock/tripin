## 1. 판정 기준이 조사 중에 두 번 뒤집혔다

### 1차: "도시를 많이 다니는 채널" → 틀렸다

**자동자막에서는 상호명이 안 잡힌다.** 실측:

곽튜브 부산 편(만덕 한우꼬리곰탕) 자동자막에서 실제로 뽑힌 것 —

```
0:04 꼬리곰탕 이랑 도가니탕 뭐 이런거 곰탕 유마 쉽게 앉아있다가
5:41 오늘 만덕 에서 골목에 맛있는 식당들이 감 잡았습니다
```

지역(만덕)·업종(꼬리곰탕)은 잡히는데 **상호가 없다.**
빠니보틀 오사카 편에서는 "유니버설 스튜디오"가 `아고 유니버설 스티어`로 뭉개졌다.
**고유명사가 자동자막이 가장 못 맞히는 부분이고, 상호명이 정확히 그 고유명사다.**

`INGEST.md` 는 "상호가 자막·검색으로 특정 안 되면 추측 등록 금지"라고 못박는다.
→ **자동자막만 있는 채널은 핀이 거의 안 나온다.**

반면 쯔양 삿포로 편(수동자막):

```
0:51 (다누키코지 상점가)
1:30 (야마다몽골) 뭔가 포스 있게 생겼어요
```

제작진이 단 화면자막이 **지역과 상호를 둘 다 명시**한다.

### 2차: "수동자막 채널" → 그보다 위가 있었다

**더보기란에 구글맵 링크를 붙이는 채널.** 오하도쿄 실제 더보기란:

```
📍시부야 / SHIBUYA
① 바쿠마츠 카레 (幕末カリー)
https://maps.app.goo.gl/ShoWEARGrEvoX38T8
② 메가돈키 시부야 본점 (MEGAドン・キホーテ 渋谷本店)
https://maps.app.goo.gl/61JDRLaBso7AnXdv7
...
⏰ 타임라인
00:34 바쿠마츠 카레(스프카레)
09:56 쇼토 카페(디저트 맛집)
```

이 한 덩어리가 우리 스키마를 **거의 그대로** 채운다:

| 필요한 것 | 더보기란에서 | 원래 어디서 얻었나 |
|---|---|---|
| `places.name` | ① 바쿠마츠 카레 | ④ LLM 자막 분석 |
| `places.name_local` | 幕末カリー | ④ LLM |
| `places.google_maps_url` → `lat`/`lng` | maps.app.goo.gl 링크 | ⑤ 지도 검색 매칭 |
| `video_places.timestamp_sec` | ⏰ 타임라인 | ③ 자막 큐 |
| 지역 | 📍시부야 | ④ LLM |

**즉 ③자막 추출 · ④LLM 장소 분석 · ⑤지도 검색 매칭이 전부 불필요하다.**
`INGEST.md` 가 "유일한 제약 구간"이라 부른 ③번도, "여기서 매칭률이 무너지면 B안이 무너진다"던
⑤번도 우회된다.

**덤으로 이 프로젝트 유일한 구조적 리스크가 사라진다.**
`INGEST.md` §3.3 은 동명이점 오확정을 유일한 구조적 리스크로 지목하고, 검색 결과가 2개 이상이면
`candidate` 강제라는 규칙을 뒀다. **구글맵 공유 링크는 지점을 특정한 링크다.**
크리에이터 본인이 다녀온 그 지점을 찍어 공유한 것이므로 동명이점 판별이 애초에 발생하지 않는다.
`sourceNote` 근거도 "영상 더보기란 ①번 링크"로 자동 충족된다.

### 3차 정정: 링크가 없어도 **주소**면 된다

또간집(§3) 을 보다가 알았다. 더보기란에 구글맵 링크가 없어도 이렇게 적는 채널이 있다:

```
15:00📍EJ보쿠조
〒595-0013 Osaka, Izumiotsu, Miyacho, 1−28 EJ牧場
```

상해기는 라벨을 아예 붙인다:

```
🏠매장명: 게장뷔페
📍위치: 서울 관악구 보라매로 34
```

**주소가 있으면 `backfill-coords.mjs` 의 2순위 경로(일본 = 국토지리원 GSI 주소검색, 무료·키 불필요)가
그대로 먹는다.** 우편번호까지 있으면 정확도도 높다. 상호·원어명·타임스탬프도 같이 들어 있다.

> ⚠️ **이것 때문에 프로브에 결함이 있었다.** 처음엔 `maps.app.goo.gl` 링크만 셌기 때문에
> 주소 표기형 채널이 전부 "지도링크 0 → 자막 의존"으로 잘못 분류됐다.
> `📍` 마커와 일본 우편번호(`〒`)를 따로 세도록 고쳤고, 재스윕했다(§2 하단).

### 그래서 최종 기준 (우선순위)

| 컨셉 | "영상으로 미리 떠나는 여행" — 유튜브 여행 콘텐츠를 도시별·장소별로 정리 | 채널×도시 조각 |

**즉 "글로벌 여행지 + 유튜브 크리에이터 + 지도"는 선례가 없는 게 아니라 이미 규모 있게 존재한다.**

다만 포지션이 완전히 같지는 않다. 낙낙이 다루는 채널은 타이거투어·MINDELI민델리·오하도쿄·
새부리·맵하니·란로그·원지의하루 등 **중소 브이로그 채널 1,336명을 넓게 훑는 스팟 우선(spot-first)**
집계다. 곽튜브·추성훈·성시경·쯔양 같은 **대형 채널이 목록에 없다.**

Tripin 이 남겨 둔 차별점으로 볼 만한 것:
- **채널 퍼스트** — "곽튜브 도쿄 맛집" 같은 채널명 포함 미드테일 쿼리를 조각 페이지가 정확히 받는다
- **조각 완성도** — 8핀 게이트 + 사람이 쓴 요약. 1,336명 얕게 vs 소수 깊게
- **대형 채널** — 구독 기반 신뢰에 기대는 원래 전제가 낙낙에는 없다

> **하지만 낙낙이 이미 오하도쿄를 다루고 있다.** 이 조사의 1순위 채널이 경쟁 서비스의
> 커버리지 안에 있다는 뜻이다. 착수 전에 **낙낙의 오하도쿄 페이지를 실제로 열어 보고**
> 우리가 무엇을 다르게 할지 정하는 게 맞다.

`PRODUCT.md` 의 Positioning 절과 "미확정 사실"은 이 발견을 반영해 고쳐야 한다.
**이건 채널 선택보다 상위의 결정이라 여기서 단독으로 처리하지 않았다.**

## 7. 8핀 게이트 현황

`MIN_CONFIRMED_PINS = 8`. 지금 통과하는 조각은 **하나뿐**이다.

| 조각 | 현재 | 후보 반영 시 |
|---|---|---|
| 추성훈 × 도쿄 | **8** ✅ | 미수집 4편으로 더 두꺼워짐 |
| 추성훈 × 후쿠오카 | 5 | 미수집분에 후쿠오카 없음 → **정체** |
| **후쿠오카 아저씨 × 후쿠오카** | 0 | **영상 3~4편이면 8핀** ✅ ← 정체된 후쿠오카를 뚫는다 |
| 일본 미식 × 오사카 | 0 | 영상 3편이면 8핀 ✅ ← **오사카 공백을 메우는 유일한 지도링크 채널** |
| 방콕킴 × 방콕 | 0 | 영상 2편이면 8핀 ✅ (신규 도시, 교차 없음) |
| 키령 × 도쿄 | 0 | 수동자막 경로. 자막 추출 필요 |
| **오하도쿄 × 도쿄** | 0 | 영상 2~3편이면 8핀 ✅ (평균 5.6곳/편) |
| 찬고리 × 후쿠오카·삿포로 | 0 | 영상 2편이면 8핀 ✅ (평균 5.1곳/편) |
| 라라부부 × 도쿄·삿포로 | 0 | 영상 4편이면 8핀 ✅ |
| 도쿄사는웅이 × 도쿄·오사카 | 0 | 영상 3~4편이면 8핀 ✅ |
| 오하도쿄 × 교토 | 0 | 신규 도시. 11편 중 2~3편 |
| 성시경 × 도쿄 | 0 | **8** ✅ |
| 성시경 × 부산 | 0 | 7 (1곳만 더) |
| 쯔양 × 삿포로 | 0 | 6편 → 자막 추출 필요 |
| 곽튜브 × 부산 | 2 | 제목에 상호 있는 편만 +2~3 |

§2 의 수집 범위 제약(조각당 3~6편)을 지키면 도시 교차는 **도쿄 8 → 30~40**,
**후쿠오카 6 → 25~30**, **삿포로 2 → 15~20**, **부산 3 → 10** 수준이 된다.
`/city/tokyo` 와 `/city/fukuoka` 가 처음으로 "여러 채널이 겹친 도시"로서 의미를 갖는다.

> 이 수치는 §2 이전 판(도시당 300~400곳)에서 크게 내려온 것이다. **범위 제약이 규모를
> 한 자릿수 낮췄고, 그 덕에 아래 확장성 경고의 시급도도 함께 내려간다.**

> ⚠️ **그래도 `HANDOFF.md` §4-3 임계값에는 닿는다.** 거기 적힌 값은 "채널 5개면 홈이 ~1MB",
> "**도시당 30곳이면 마커가 겹친다**", `loadGraph` 가 테이블 전체를 읽어 **PostgREST 행 상한에서
> 조용히 잘린다**는 것이다. 범위 제약을 지켜도 채널이 5개 늘고 도쿄가 30~40곳이 되므로
> **마커 클러스터링과 로더 필터는 여전히 선행돼야 한다.** 홈 페이지네이션도 채널 5개 선에 걸린다.
>
> `HANDOFF.md` §7 이 이미 "로더 정리가 지금 제일 싸다"고 적어 뒀고, 이 조사가 그 이유를
> 수치로 확인해 준 셈이다.
>
> **시작은 후쿠오카 아저씨 하나로.** 단일 도시라 폭발 범위가 좁고, 정체된 후쿠오카 조각을 뚫으며,
> 영상 3~4편이면 게이트가 차서 §3.2 범위 제약과도 가장 편하게 맞는다.

## 8. 부수적으로 확인된 것

- **자막 파이프라인(IOS 클라이언트 우회)이 아직 살아 있다.** `INGEST.md` 가 "막히면 클라이언트
  버전을 갱신하라"고 적어 둔 구간인데 2026-08-09 기준 정상이다. 손댈 필요 없다.
- YouTube API 쿼터는 이 조사 전체(채널 40개+ 프로브, 더보기란 400편 전수)를 돌리고도 여유롭다.
  `probe-channel.mjs` 는 채널당 ~5 units, `--pages=20` 전수도 ~40 units. 하루 한도 10,000.
- `search.list` 는 쓰지 않았다(100 units — `INGEST.md` §2-① 금지).
  **발굴은 웹 검색, 검증은 `channels.list`/`playlistItems.list`/`videos.list`(각 1 unit)** 로 갈랐다.
- macOS 기본 `grep -oE` 는 한글 다중 패턴에서 오작동한다(엉뚱한 카운트). 집계는 python 으로 하라.
- 이 머신의 python 3.9 는 SSL 인증서 검증에 실패한다. HTTP 는 `curl` 로 받아서 파싱하라.
